# 故障机器人 · 互动桌宠 v23

v23 将充能球从水平直线改为围绕机体上方的弧形槽位，中间高、两侧低；默认三槽与扩容五槽分别调整横向半径，保留轻微浮动。球体绘制、点击区域、空槽提示、入槽终点、被动特效和激发起点共用同一位置，实际球序与激发规则保留。

v22 修正机器学习的卡面理解：去掉新增的三条触手，改动原本的颈部和后侧两根电线。头部轻抬 18 个画面单位，颈部和原电线同步伸展，连接点固定在围巾内；青绿电路变色只覆盖原本可见的机械结构，并保留头部大小、眼部、围巾和手臂遮挡。动作结束后原颈部收回，能力期间保留电路头，获得集中时亮起。聚变和超频压力表保持原样。

v21 新增机器学习、聚变两段独立机体动作，共 306 个 60 Hz 采样，总采样 3272 帧。机器学习用爪子轻触头侧，原头部转为卡面式青绿电路材质，三条分节电路带展开；能力生效时保留电路头，每使用四张牌获得集中时再次闪亮，冷静头脑的蓝色头部优先显示，充电夹头继续随动。聚变以冰蓝晶束、金黄电流和紫色暗流汇入青绿多瓣亮核，收缩闪光后形成一颗原版等离子球入槽；保留回响、满球槽和原有卡牌规则。

v20 将超频压力表整组缩小 10%，再上移 30 个画面单位，使指针、中心轴和火焰完整露出，避免头部遮挡；保留红热核心和原来的动画节奏。

v19 保持超频环、火焰、指针的大小与动画节奏，将整组压力表向左移动 42、向上移动 86 个画面单位，避开头部。环播放期间顶部文字提示暂时让位。炽红核心和少量黄色亮面保留。

v18 将超频时原本蓝色的胸腔核心替换为同质感的炽红核心，只有最亮的晶面带少量黄色；保留原图的晶面、明暗、机械补丁和围巾/手臂遮挡。全部 21 段动作的 2966 帧均有对应核心材质，热态随其他动作保持，轻微脉动后在五秒结束前冷却回蓝色。安静模式保留红色材质。压力表与冰之长枪保持 v17 的回退版本及枪头修复。

v17 将超频和冰之长枪恢复为 v15 的表现，包含原有压力表位置、火焰、握枪姿势、枪头大小、风效与突刺幅度；其他卡牌保留。冰枪额外修复枪杆伸到枪尖、凝结时枪头与枪柄脱节、突刺时枪头长度变化和命中瞬间的小方块；增加短冰晶套口，碎片改为渐出的旋转三角冰片。以下为历史记录。

v16 将超频压力表改到头部正上方，横向与头部中心对齐；激活期间暂让出顶部对白位置。火焰替换为连续翻卷的多层火冠、暗红焰穴与上升余烬。冰枪改为宽刃冰晶重枪，枪头加长加厚，增加副晶棱、裂隙和卷风；双手后撤抱枪、整机前送突刺，命中出现半面霜爆与更大的碎晶。五秒热态、降温和两颗实际冰霜球规则继续保留。

v15 为冰之长枪和超频新增两段原版骨架动作，264 个 60 Hz 采样。冰枪改为真正的双手冰晶长兵器：枪身凝结、握持蓄势、前送突刺、冰刃崩裂与碎晶回流；两颗冰霜球的逻辑保持原样。超频采用卡面烧红压力表与金色指针，核心变成橙白高热核心，五秒能力期间有电流和双侧排汽，结束后降温；切换其他卡牌时热态仍跟随实际能力状态。两段动作同步生成蓝色头部与充电夹头绑定，总采样 2966 帧。

v14 为爪击和球状闪电增加两段原版骨架动作，共 210 个 60 Hz 采样，并同步制作头部、蓝色改色与夹头绑定。爪击以张开的原版机械爪蓄势、重划、短停和收爪，配卡面式冰蓝刃边与橙红灼痕，连击会加厚切痕。球状闪电在机械爪中聚起大金黄雷球，前推发射后爆裂，电荷再回到真实的闪电球槽；只延迟显示入槽，不改逻辑球数量、集中或回响规则。总动作帧数 2702。

v13 重做雷暴：以原版雷暴卡面的深紫旋云、白色主闪电、黑色描边与紫红电晕为依据。肩背上方改为约 270×150 的分层厚云，云眼蓄亮后于 0.54 / 1.12 / 1.70 秒释放三轮粗分叉雷击，双侧错峰落地，加入机体受光与地面余电。云层与上方电弧置于机体后方，前景雷击避开头部；整体 2.5 秒，能力规则和原版图标保留。

v12 加强闪电双放：白蓝主雷柱投影宽度 58/65，双落点错开放在右前方，球源连接保持在窗口内，加入分叉与原版命中闪光。雷霆根据原版卡面采用金黄、赭金分面和深紫暗部，肩背四束不对称电流、0.42 秒涌动、双臂原版雷电形状与机体暖色受光；能力触发的追加雷击也使用同一配色。保留双放规则、其余三类球、36 张卡牌和头部绑定。

v11 重新对照本地订阅“更多机器人动画”v0.17.1 的 Multicast 系列实现，只修改双放：闪电分叉落雷、冰霜六条寒流绕身、黑暗紫粉平滑拖尾、等离子青金回流至脚下能量槽。双放使用模组的平滑分支，取消旧版锯齿轮廓、星形弹头与外围放射碎片。保留两次激发间隔 0.24 秒、只消耗一颗球和现有 36 张卡牌。WPF 二维适配，不运行模组程序集。

## 和它玩

| 操作 | 回应 |
| --- | --- |
| 轻点机器人 | 电击：生成一颗雷球；单击会等待系统双击判定时间，通常约半秒 |
| 双击机器人 | 双重释放：最右侧的一颗球连续释放两次 |
| 轻点任意充能球 | 释放这一颗球 |
| 按住机器人不动 | 约 0.55 秒进入充电；松开获得能量；按满约 1.8 秒获得两格 |
| 按住后立即拖动 | 移动桌宠；放手后跳跃落地 |
| 右键机器人 | 展开 36 张卡牌；按充能球、攻击、能力、机能筛选，或输入名称搜索 |
| 选牌界面底部箭头 / 键盘左右键 | 翻页，每页 12 张；搜索框输入时左右键仍用于编辑 |
| 左键卡牌 | 出牌；选中的卡牌会短暂显示在机器人旁边 |
| 在选牌界面再次右键 / 按 Esc | 取消选牌；点击别处也可收起 |
| 脚下能力图标 | 常驻显示当前能力及数字；悬停或点击查看具体说明 |

默认三个充能球槽，使用“扩容”增加到五个。新球从左侧进入，最早的球在最右侧。满槽时，新球挤出并激发最右侧的球。能量最多三格，可增强下一次激发。双重释放的两次脉冲间隔 240 毫秒，共享这次强化。

四种球采用本机《杀戮尖塔 2》的原版透明贴图。36 张卡牌用原版画面、卡框、稀有度横幅和能量图标组合显示，中文名称经本机游戏文本核对。卡牌文字标注“桌宠效果”，描述本程序实际互动；这些效果是桌宠改编。所有卡牌均可自由使用，卡面能量数字不会限制出牌。

| 机器学习 | 每再出四张牌增加一点集中，最多五点 |
| 超频 | 储能充满，核心持续运转五秒，之后散热 |

持续能力在当前运行中保留；集中和爪击有上限。重启会清除全部持续能力、集中和连击，恢复三个球槽。重新打开程序也会开始新的一轮。

原有 12 张保留：

- **冷静头脑**：生成冰霜球，激发时原版冰晶粒子在机体周围展开。
- **漆黑**：生成黑暗球，每等待 8 秒增强一次释放，最多增强三次。
- **聚变**：生成等离子球，释放后补充一格能量。
- **彩虹**：依次生成闪电、冰霜和黑暗球，球从掌心飞入球槽，也会遵守满槽时的激发规则。
- **全息影像**：记住并重演上一招，伴随半透明残影；不会无限重演自己。
- **回响形态**：下一招由延迟的青色残影再执行一次，能与全息影像组合。
- **火箭飞拳**：原版机械爪向前击出，带电弧和短暂停顿。
- **飞跃**：原版姿势配合短暂离地与落地反馈。
- **重启**：机体先暗下，再重新点亮；清空球槽、能量、回响和上一招的记忆。
- **充电**：既可按住机器人蓄力，也可直接在卡牌中选择“充电”。

闲置 45 秒后，它会安静等待；球槽未满时会生成一个冰霜球。闲置陪伴不会消耗回响，也不会挤掉已有的球。

## 日常使用

- 系统托盘的“大小与设置”中可调整大小、置顶和安静模式。安静模式减少粒子、光环和对话气泡。
- 选择“暂时收起”后，可在 Windows 系统托盘中双击机器人图标找回，也可再次运行启动文件。
- 在系统托盘菜单中选择“退出”关闭程序。
- 位置、大小和偏好保存在 `%LOCALAPPDATA%\DefectCompanion\settings.txt`。退出后可删除该文件恢复默认设置。
- 程序离线运行，不需要账户、Python、Node.js、管理员权限或联网服务。未设置开机自启。
- 适用于 Windows 10 / 11，使用系统自带的 .NET Framework 4.8。跨显示器不同缩放比例和全屏游戏上的显示行为尚未做完整测试。

## 修改与编译

v5 的 `NativeAnimation.cs` 播放原版动作，`NativeClips.Generated.cs` 保存时长、裁切区域和逐帧骨骼坐标。`native-study/study.gd` 检查原版动作，`native-study/export.gd` 使用游戏自带 Spine 运行时逐帧输出，再运行一次 `prepare_native_animation.py` 裁切并生成坐标；不能对已经裁切的图集重复打包。工程游戏路径需要按本机调整。源码包已有完整素材，重新编译无需启动游戏。旧版运动图集和生成工具仅供历史参考，v5 不加载旧版角色运动图集。

源码包包括 `Main.cs`（透明窗口、输入和托盘）、`CardEffects.cs`（新增特效）、`PetEngine.cs`（卡牌和球槽规则）、`CardPicker.cs`（筛选、搜索和分页）、`GameArt.cs`、`CardCatalog.Generated.cs`、`card_catalog.json`（统一卡牌目录）、测试、素材、清单和配置文件。

在 Windows PowerShell 中运行 `build.ps1`。它使用 Windows 系统的 .NET Framework C# 编译器，不下载依赖，并先执行交互规则测试。成品在 `release` 文件夹。也可通过 `-OutputDirectory` 指定其他输出文件夹。

`DefectCompanion.exe --preview <文件夹>` 可将程序自己的四个演示画面及选牌界面渲染为 PNG，用于检查构图；此模式不会写入日常设置。

`DefectCompanion.exe --ui-test <文件夹>` 在独立测试进程中检查卡牌窗口、右键取消、Esc 取消、选牌后技能执行及贴图加载，报告保存到指定文件夹。该检查使用程序自身的 WPF 界面事件，不代表外部鼠标注入测试。

`DefectCompanion.exe --benchmark <文件夹>` 在独立透明窗口中测量真实 WPF 绘制调用：预热两秒、三球待机六秒、连续出牌八秒，输出 `frame-performance.json`。它记录绘制速率和帧间隔，不代表逐帧测量显示器最终呈现的画面。

`AnimationTiming.cs` 管理显示刷新节奏和拖动方向稳定，`PerformanceCheck.cs` 提供上述测量。`smooth_animation.py` 与 `build_run_cycle.py` 是旧版动画制作记录，v5 不再加载或打包其运动图集。v5 运行和编译均不需要 OpenCV 或 Python；只有重新制作原版动画素材时才需要额外工具。

`expand_cards.py` 从本机游戏核对中文名称与画面文件，生成 `card_catalog.json` 和 `CardCatalog.Generated.cs`。重新制作素材时，依次运行 `expand_cards.py`、`extract_game_assets.py`、`compose_cards.py`，再运行 `build.ps1`。

`PowerStatus.cs`、`PowerBar.cs` 管理能力状态与原版图标栏。`extract_style_assets.py` 只读提取 29 项图标与特效资源，将原版 shader 调色和扫射投影预处理为离线图片；制作时需 Pillow、NumPy、OpenCV。`assets/style-sources.json` 记录原版路径、输出尺寸和哈希。运行 `--ui-test` 还会输出六张主要卡牌在四个时刻的独立画面，便于检查蓄力、释放和消散。

`extract_game_assets.py` 记录了本次从游戏资源中导出素材的过程，`compose_cards.py` 记录了原版卡牌分层、配色参数和中文排版过程。它们属于制作工具，修改时需要 Python、Pillow 和 NumPy；运行桌宠不需要这些环境。`assets/sources.json` 记录导出路径和文件哈希。源游戏素材归 Mega Crit 所有。
